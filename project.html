Overview

In teams of 3–4, you will ask an empirical question about a computer vision model and answer it with evidence. You'll start from open-source code, and the course provides no base code: working with a real repository is part of the skill.

The one rule that shapes everything else: frame your project as a question with a measurable answer, not as "build X." "Build a self-driving car" fails. "Does this detector degrade more on night images than on rain images?" can be answered well with 40 photographs. Any topic can host a good question, and one rubric grades the evidence regardless of topic. Proposals phrased as a build will be sent back with one instruction: turn this into a question.

The final project counts for 35% of your course grade. It is the course's final-week activity, and there is no final exam.

What Each Milestone Requires

Project Lab 1 and the project seed (Oct 7, seed due Oct 11, participation)

In the first lab you'll watch several modern models succeed and fail, predicting what happens before each demo. You leave with a project seed: a domain you care about, five images you could get from it, and a prediction of where a model would work and where it would fail.

Project Lab 2 and team roster (Oct 12, roster due Oct 16, participation)

Pitch your seed in 60 seconds to rotating small groups, then form teams of 3–4 (the exact size is set in week 1, once enrollment settles). Anyone still without a team on Oct 16 goes on the unmatched list, and the TA places them on teams on Oct 19.

Proposal (Oct 28)

Keep it to one page:

  • The question
  • Your archetype (below)
  • The repository you'll start from
  • A data plan
  • A baseline plan
  • A fallback, if you chose archetype 6

Include the smoke test: the actual console output of the repository's own demo or evaluation running on your setup. Paste the output itself, not a plan to run it. If a repository won't run within a few hours, pick a different one. Learning that in week 5 costs nothing; learning it in week 9 costs the project.

Check-in (Nov 18, before class)

Your check-in must include a baseline number. A baseline is a simple method with a measured result: random guessing, nearest neighbour, zero-shot CLIP, or the repository's off-the-shelf output. It guarantees you have something to report even if the ambitious part doesn't work. It is also the only way a later result means anything: 87% accuracy is uninterpretable until you know guessing gets 70%. Also include your revised scope and what's blocking you. A team that arrives without a baseline number will have its scope cut down to something achievable. That's a rescue, not a penalty.

Presentation (Nov 30 or Dec 2)

The format (full talks, lightning talks, or a mix) will be announced on Nov 9, once enrollment is known.

Video + code (Dec 7)

Submit all of the following:

  • A 4–5 minute video in a fixed order: question, baseline, what you did, result, limitation.
  • A GitHub fork of the repository you started from, submitted as a URL.
  • A CONTRIBUTION.md file listing every file your team wrote or changed, with one line on why.
  • Your results.

Six Project Archetypes

Pick one of these shapes. Follow the shape and you will have results by Dec 7. Archetypes 1–5 rely mostly on running existing models rather than training new ones, which is what makes them work on free Colab.

Project archetypes, what each produces, and its risk
Archetype What you produce Risk
1. Reproduce and stress-testReproduce one reported number from an open-source model, then break it on out-of-distribution data you collect. You produce the reproduction plus a robustness curve.Lowest
2. Head-to-head under a fixed budgetCompare 2–3 open-source models on the same task, data, and compute. You produce a comparison table and a recommendation you defend.Low
3. Domain transferApply a model trained for one domain to a domain you care about, measure the drop, then try to close it. You produce before/after results and a gap analysis.Low
4. Ablation / mechanism probeSystematically remove or change parts of one model to find what matters. You produce an ablation table and an explanation.Low
5. Failure taxonomyCollect inputs where a model fails, sort the failures into categories, and test hypotheses about their causes. You produce the taxonomy with evidence for each category. No training needed.Low
6. Build something newBuild a working system, plus its evaluation.High: your proposal must name a fallback from archetypes 1–5 using the same repository and data

The course never covers multi-view geometry (homographies, calibration, stereo, structure from motion). You may still propose a project on it, but you'll be learning that material on your own.

Choosing a Starting Repository

A vetted list of starting points, each confirmed to install and run on free Colab this quarter, will be posted with the project handout on Oct 21. You may go off the list if your repository meets the same bar:

  • The README has a working install and a runnable demo or evaluation command.
  • It had a commit in the last ~2 years, or it's a maintained library such as torchvision, timm, or Hugging Face.
  • It's an official implementation, or it has a few hundred or more stars.
  • Pretrained weights are downloadable. Avoid anything that says "train for 8 GPU-days".
  • It runs on one GPU, meaning free Colab.

Grading Rubric

One rubric covers every project, so an ambitious topic is never graded as "harder" than a modest one. The rubric grades the evidence you show. Each dimension is scored 0, 1, or 2:

  1. There is a question, stated precisely enough to be answerable.
  2. There is a baseline with a number, and it's the right baseline.
  3. There is a comparison or a curve, not a single number.
  4. The evaluation is honest: held-out data, no tuning on test data, limitations stated.
  5. The conclusion follows from the evidence shown, and goes no further.
  6. Your contribution is clearly separated from what the repository already did. This is checked against your fork's diff and your CONTRIBUTION.md.
  7. It's reproducible: someone could re-run it from what you submitted.
